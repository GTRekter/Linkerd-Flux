# Linkerd-Flux

GitOps deployment of Buoyant Enterprise for Linkerd (BEL) with Flux, following the [BEL installation guide](https://docs.buoyant.io/buoyant-enterprise-linkerd/latest/installation/install-guide/) (Helm method).

## Prerequisites

- [Docker](https://docs.docker.com/get-docker/)
- [k3d](https://k3d.io/)
- [kubectl](https://kubernetes.io/docs/tasks/tools/)
- [flux](https://fluxcd.io/flux/installation/#install-the-flux-cli)
- [step](https://smallstep.com/docs/step-cli/installation/) (certificate generation)
- A valid Buoyant Enterprise for Linkerd license
- A GitHub personal access token with `repo` scope

## Architecture

Flux reconciles a single Kustomization from `./overlays`:

```
flux-system (bootstrap)
    └── linkerd-buoyant    BEL CRDs + control plane (namespace: linkerd)
                           + lifecycle operators   (namespace: linkerd-buoyant)
```

Ordering between the Helm charts is enforced with HelmRelease-level `dependsOn`:

```
linkerd-enterprise-crds → linkerd-enterprise-control-plane
```

The `linkerd-buoyant` operator release is independent and installs in parallel.

| Stage | Chart | Version |
|---|---|---|
| linkerd-buoyant | `linkerd-enterprise-crds`, `linkerd-enterprise-control-plane` | 2.19.0 |
| linkerd-buoyant | `linkerd-buoyant` (lifecycle operators, Buoyant Cloud disabled) | 0.40.2 |

There is no secret automation on this branch. The license and mTLS certificates are created manually as Kubernetes Secrets before bootstrapping:

| Secret | Namespace | Keys | Used by |
|---|---|---|---|
| `linkerd-certs` | `linkerd` | `ca.crt`, `issuer.crt`, `issuer.key` | Injected into the control plane chart via `valuesFrom` (`identityTrustAnchorsPEM`, `identity.issuer.tls.crtPEM/keyPEM`) |
| `buoyant-license` | `linkerd` | `license` | `licenseSecret` value of the control plane chart |
| `buoyant-license` | `linkerd-buoyant` | `license` | `licenseSecret` value of the operator chart (required because `buoyantCloudEnabled` is false) |

Webhook certificates (proxy injector, policy validator, sp validator) are generated by Helm at install time — the chart defaults.

## Repository Structure

```
.
├── base/
│   └── linkerd-buoyant/           # BEL CRDs + control plane HelmReleases
└── overlays/
    ├── kustomization.yaml         # Top-level entry point (flux bootstrap path)
    ├── flux-kustomizations.yaml   # Flux Kustomization for the linkerd-buoyant stage
    └── linkerd-buoyant/           # Env-specific patches (version, log levels)
```

## Setup

### 1. Create the k3d cluster

```bash
k3d cluster create linkerd \
  --k3s-arg "--disable=traefik@server:*" \
  -p "80:80@loadbalancer"
```

Verify the cluster is running:

```bash
kubectl cluster-info
kubectl get nodes
```

### 2. Generate the mTLS trust anchor and issuer certificates

Per the BEL install guide:

```bash
step certificate create root.linkerd.cluster.local ca.crt ca.key \
  --profile root-ca --no-password --insecure

step certificate create identity.linkerd.cluster.local issuer.crt issuer.key \
  --ca ca.crt --ca-key ca.key --profile intermediate-ca \
  --no-password --insecure
```

### 3. Create the namespaces and secrets

Export your license (from [enterprise.buoyant.io](https://enterprise.buoyant.io)):

```bash
export BUOYANT_LICENSE=<YOUR_LINKERD_LICENSE>
```

Create the namespaces (Flux adopts them on bootstrap) and the secrets:

```bash
kubectl create namespace linkerd
kubectl create namespace linkerd-buoyant

kubectl create secret generic linkerd-certs -n linkerd \
  --from-file=ca.crt --from-file=issuer.crt --from-file=issuer.key

kubectl create secret generic buoyant-license -n linkerd \
  --from-literal=license=$BUOYANT_LICENSE

kubectl create secret generic buoyant-license -n linkerd-buoyant \
  --from-literal=license=$BUOYANT_LICENSE
```

### 4. Bootstrap Flux

Bootstrap Flux on the cluster:

```bash
flux bootstrap github \
  --owner=GTRekter \
  --repository=Linkerd-Flux \
  --branch=simple \
  --path=./overlays \
  --personal
```

When prompted, paste your GitHub personal access token (or set it beforehand via the `GITHUB_TOKEN` environment variable).

This installs Flux and configures it to reconcile the Kustomization defined in `overlays/flux-kustomizations.yaml`.

If you bootstrap before seeding the secrets, the HelmReleases fail initially and retry automatically (`remediation.retries: -1`) until the secrets from step 3 exist.

### 5. Verify the deployment

Watch Flux reconcile the stage:

```bash
flux get kustomizations --watch
```

It should show `Ready: True`:

```
NAME            READY   MESSAGE
linkerd-buoyant True    Applied revision: main@sha1:...
```

Check the HelmReleases and workloads:

```bash
flux get helmreleases --all-namespaces

kubectl get pods -n linkerd
kubectl get pods -n linkerd-buoyant
linkerd check
```

## Cleanup

```bash
k3d cluster delete linkerd
```
